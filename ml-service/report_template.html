Cognitive-state model · training run

How the model was trained and tested

Synthetic data. These participants were generated by backend/scripts/seed-mock-pilot.ts, so the scores describe the mock-data generator, not real learners. This run only shows that the pipeline works end to end.

From check-ins to a model the app can use

    npm run dev never trains. It starts the services, and the ML service loads the run that MODEL_RUN in ml-service/.env names, then only predicts. Training is a separate command (npm run train). Each run writes a new folder like this one, and the app keeps using the old model until MODEL_RUN points at the new one.

    The data

    The labels come from the learners: the answer they picked in a check-in pop-up. The model has to guess that answer from the camera and mouse features of the minute before the pop-up appeared.

    What people answered in the check-ins

    Who trains and who tests

    One person's check-ins look alike, so if the same person were in training and in test, the score would be too good. The split is therefore made by person. In each fold, about a fifth of the people are test people. Of the rest, are validation people, used only to decide when to stop training, and the model learns from the remaining training people. Every person is a test person in exactly one fold.

    How well it does on people it never saw

    Every check-in below was predicted by the model of the fold in which that person was a test person. Macro-F1 averages the F1 score of the four states, so a rare state counts as much as a common one. Each bar is the mean over the folds (± its spread across folds). Hover a bar for the single folds.

    Where the LSTM gets it right and wrong

    Rows: what the person answered. Columns: what the model predicted. The shading shows the share of the row.

    Recall: of the check-ins where people gave this answer, the share the model got right. Precision: of the model's guesses of this state, the share that were right.

    Look inside single check-ins

    Pick a check-in. The grid is what the model reads: 13 features × 12 five-second windows, oldest on the left. The colour shows each value compared with the average window (blue = lower, red = higher). Hover a cell for the raw value. The model outputs four probabilities, and the highest one is its prediction.

    Where this is decided

    All of these are set at the top of ml-service/train.py or on its command line.

    Run it again

    npm run train -- --data synthetic   # the mock participants (pipeline check)
npm run train                       # real participants (P-codes), the default
